## A. 仕様内の矛盾・誤記

### A1 JSX のテキスト子は使えない
- 決定: `<Label>text</Label>` のテキスト子は診断する。文字列は `{"text"}` と書く。
- 理由: 空白の正規化規則は決定性の罠になる。仕様の例でも使っていない。
- 仕様: 修正（§3 のテキスト子の文を削除、付録B の該当項目を閉じる）
- 改訂（2026-11-12）: テキスト子を許可に変更した。R1 を参照。この項目の決定は R1 で置き換わっている。

### A2 `c && <A />` は禁止
- 決定: E3。help に `c ? <A /> : undefined` を示す。
- 理由: §5 本文どおり。
- 仕様: 修正（付録B の該当項目を閉じる）
- 改訂（2026-11-12）: `c && <A />` を許可に変更した。R2 を参照。この項目の決定は R2 で置き換わっている。

### A3 関数の型注釈
- 決定: `function`、トップレベルの `const f = (…) => …`、ポリシーのメンバーでは、引数と戻り値の注釈を必須にする。組み込みメソッドの引数に直接書いたアロー関数リテラルだけは、引数と戻り値の型を文脈から推論する。
- 理由: §6 の例 `binds.map((b) => …)` がそのまま通る。推論が要る場所は 1 か所に限られる。
- 仕様: 修正（§4「関数の引数と戻り値には注釈が必須」の文）

### A4 `if` には `else` が必須
- 決定: `else` のない `if` は書けない。ガード節（`if (c) { return a; }` に続けて文を書く形）も認めない。
- 理由: ブロックの末尾に置ける stmt は 1 つで、全経路が `return` で終わる必要がある。今の文法と規則に合い、フロー解析が要らない。
- 仕様: 修正（§5 の EBNF `if` から `[ ]` を外す）

### A5 E3 と E4 の境界
- 決定: ホストの組み込みコンポーネントについての検査は E4 にする。対象は props の欠落・余分・型の違い、子の型、ルート要素、子の一意性。それ以外のオブジェクト型の検査は E3 にする（ユーザーのコンポーネントや型も含む）。
- 理由: §10 の例とおおむね合う。ホストに起因する誤りを独立した帯で区別できる。
- 仕様: 修正（§10 のコード帯の例を明確にする）

### A6 `satisfies` とポリシーの完全一致
- 決定: 関数型は不変（同一の型どうしだけ代入可能）にする。そうすれば `satisfies` は一般規則（代入可能性）のままで、フックの型は完全一致になる。フックはすべて省略可能。ホストが宣言していないフック名は E4。
- 理由: 「完全一致」という特別な規則を新たに作らずに済む。
- 仕様: 修正（§8 の規則に、関数型の不変性とフックの省略可能性を書く）

### A7 誤記の修正
- 決定: 次のとおり読み替えて実装する。
  - §10 の E3 の例「`match` の網羅性」は「`switch` の網羅性」と読む。
  - §3 で「単位つきの値は…」の段落が 2 回出てくるのは重複で、1 つにする。
  - §11 で欠けている図は、CLAUDE.md の「リポジトリ構成と依存の向き」と同じ内容とみなす。
  - §11「Contrast のプロトタイプ段階に限り」は「CDL のプロトタイプ段階に限り」と読む。
- 仕様: 修正

## B. 型システム

### B1 部分型
- 決定: 不変なコンテナは共変にする（配列・タプル・Record・オブジェクトのフィールド・`Element<…>`）。幅部分型は認めない。関数型は不変（A6）。
- 理由: `Element<Keybind>` を `Element<A | B | Keybind>[]` に入れるために共変性が要る。値は不変なので、共変にしても健全性は保たれる。
- 仕様: 修正（§4「部分型はユニオンの包含に限る」の文）

### B2 ユニオンの範囲
- 決定: 認めるのは、リテラル型どうしのユニオン、`T | undefined`、`Element<A | B>` だけ。オブジェクト型どうしのユニオンや `string | number` は E3。
- 理由: `typeof` も判別の構文もないので、それ以外のユニオンは絞り込めない。
- 仕様: 追記（§4）

### B3 `const` の型推論
- 決定: TypeScript と同じにする。プリミティブのリテラルで初期化した `const` はリテラル型を持つ。オブジェクトや配列の中のリテラルは基本型に広げる。文脈型（注釈や引数の型）があれば、そちらを優先する。
- 仕様: 追記（§4）

### B4 配列リテラルの要素型
- 決定: 要素型は、各要素の型を広げたもののユニオンにする。空配列 `[]` には注釈が必須。タプル型は、注釈か文脈型があるときだけ付く。
- 仕様: 追記（§4）

### B5 `Element<C>` とフラグメント
- 決定:
  - `C` に書けるのは、ホストの組み込みコンポーネント名とそのユニオンだけ。
  - ユーザーのコンポーネントの戻り値型は `Element<…>` に限る。フラグメントや `undefined` は返せない。
  - フラグメントの型は、子を平坦化した配列 `Element<…>[]`。
- 仕様: 追記（§4）

### B6 children
- 決定: 子はいつも、平坦化して `undefined` を除いた配列として渡す。`children` の型は `Element<…>[]` で、省略可能にしてもよい。`children` 属性と JSX の子を両方書いたら E3。
- 仕様: 追記（§6）

### B7 プロパティの省略と `undefined`
- 決定: プロパティがないことと、値が `undefined` であることを区別しない。`k={undefined}` と明示してもよい。値木では、値が `undefined` の props とフィールドを省く。配列の中の `undefined` は値として残す。
- 仕様: 追記（§4・§6）

### B8 再帰型の禁止
- 決定: `type` と `interface` の参照が循環していたら E2。
- 理由: 再帰型を禁じれば、自己適用 `f(f)` に型が付かず、停止性が守られる。値は有限の木なので、再帰型がなくても困らない。
- 仕様: 追記（§4・§7）

### B9 関数を値として扱う
- 決定:
  - 関数型を、引数やオブジェクトのフィールドの型として使ってよい。
  - トップレベルの宣言どうしの参照グラフは DAG でなければならない。呼び出しだけでなく、名前が現れる箇所はすべて辺に数える。
  - Document の値木に関数は入れられない。関数型の props は、スキーマのビルダーで拒否する。
- 理由: 参照グラフが DAG で、再帰型もない（B8）ので、単純型付きラムダ計算と同じく強正規化性が成り立つ。
- 仕様: 修正（§7「呼び出しグラフ」を「参照グラフ」に）

### B10 ジェネリクス
- 決定: ユーザーはジェネリクスを定義できない。使えるのは組み込みの `Array<T>`、`Record<string, T>`、`Element<C>` だけ。
- 仕様: 追記（§4）

### B11 単位つきの値の演算
- 決定:
  - Length: 内部表現は f64 の px で、負の値も許す。演算は L±L、L×n、n×L、L÷n（結果は Length）。L÷L はできない。
  - Duration: 内部表現は i64 のミリ秒。演算は Length と同じ。結果が整数ミリ秒にならなければ E5（`ms(1.5)` も含む）。
  - `<` などの比較は、同じ単位どうしでだけできる。
  - Color にできるのは `===` / `!==` だけ。
- 仕様: 追記（§4）

### B12 `color()` の書式
- 決定: `#rgb`、`#rgba`、`#rrggbb`、`#rrggbbaa` を受け付ける。大文字・小文字は区別しない。検査は評価時に行い、不正な書式は E5。
- 仕様: 追記（§4）

### B13 演算子と型
- 決定:
  - `+` は number・Length・Duration に使う。文字列はテンプレート文字列でつなぐ。
  - `< <= > >=` は number・Length・Duration に使う。
  - `=== !==` は、プリミティブ・リテラル・単位つきの値・`undefined` に使う。オブジェクト・配列・要素を比べたら E3。重なりのない型どうしを比べても E3。
  - 単項の `-` を許す。`**` とビット演算は入れない。
- 仕様: 追記（§5 の式の項目）

### B14 型の絞り込み
- 決定:
  - 対象: 識別子と、`a.b.c` の形のパス。
  - `=== undefined` と `!== undefined` による絞り込みは、`if`・`?:`・`&&`・`||` で効く。
  - `switch` の各 `case` の中では、判定する値がその case のリテラル型に絞られる。
- 仕様: 追記（§4）

### B15 組み込みメソッド
- 決定: メソッドは配列にだけある。`map((x) => U)`、`filter((x) => boolean)`、`reduce((acc, x) => A, init)`（初期値は必須）、`includes(x)`（`===` で比べられる型に限る）、`concat(arr)`、それに `length`（プロパティ）。コールバックは添字を受け取らない。Record と文字列には、メソッドも `length` もない。
- 仕様: 修正（§5「配列・レコードの操作」の文）

### B16 Record
- 決定:
  - 作り方: 注釈か文脈型が `Record<string, T>` であるオブジェクトリテラル。
  - 参照: `r["k"]` と `r[k]` だけ。結果の型は `T | undefined`。ドットでは参照できない。
  - キーの順序: UTF-8 のバイト順（`BTreeMap<String, _>` と同じ）。
- 仕様: 追記（§4）

### B17 添字
- 決定: 配列 `a[i]` で、`i` が範囲外・負・整数でないときは `undefined` を返す。タプルを範囲内のリテラルの添字で参照したときは、要素の型そのものになる。
- 仕様: 追記（§5）

## C. 構文と字句

### C1 使える TypeScript の構文
- 決定:
  - 使えるもの: 省略プロパティ `{ keys }`、末尾カンマ、任意の式の位置での `satisfies`、`import type`。
  - 使えないもの（診断する）: 分割代入（引数を含む）、`enum`、import の改名、既定引数・省略可能引数、計算プロパティ名、メソッド構文、`interface … extends`、交差型、型演算子（`keyof` など）、正規表現、BigInt、`**`、ビット演算、カンマ演算子、`export { … }` と再エクスポート、ブロック内の関数宣言。
- 仕様: 修正（付録B の項目を閉じ、§5 に一覧を追記）

### C2 `switch`
- 決定: EBNF のとおりにする。1 つの case に stmt は 1 つで、ブロック、複数ラベルの共有、フォールスルーはない。case が重複したら E3。判定する値の型がリテラルのユニオンでないときは、`default` が必須。
- 仕様: 追記（§5）

### C3 キーワードをプロパティ名に使う
- 決定: プロパティ名には使える（`{ default: 1 }`、`a.type`、`<X type="…" />`）。束縛の名前には使えない。
- 仕様: 追記（§3）

### C4 Hooks・イベント・`ref`・`key`
- 決定: 次はそれぞれ専用の診断にする。`user` のような名前は使える。
  - 名前が `use[A-Z0-9_]` で始まる宣言と参照
  - `on[A-Z]` で始まる属性
  - `ref` 属性
  - `key` 属性

  `key` による要素の同一性は、プロトタイプには入れない。ホストは位置で差分を取る。
- 仕様: 修正（§3「use で始まる名前」の範囲を明確にし、付録B の `key` の項目を閉じる）
- 改訂（2026-11-12）: `key` 属性を許可に変更した（`ref`・`on[A-Z]`・`use[A-Z0-9_]` は従来どおり E1007）。R3 を参照。

### C5 コンポーネント名と呼び出し方
- 決定: コンポーネント名は ASCII の A–Z で始める。小文字で始まるタグは診断する。コンポーネントは JSX からだけ使え、関数として呼び出すことはできない。props の引数はちょうど 1 つ。
- 仕様: 追記（§3・§5）

### C6 シャドーイングの禁止
- 決定: 次の名前と同じ名前を、内側で宣言することはできない。
  - 組み込み（prelude）の名前
  - import した名前
  - 外側のスコープの名前
- 理由: 診断がはっきりする。「迷ったら入れない」。
- 仕様: 追記（§5）

### C7 束縛の評価順
- 決定:
  - トップレベルでは宣言の順序を問わない。参照グラフのトポロジカル順に評価し、順位が同じものはソースの順に並べる。
  - ブロックの中では、前に宣言した名前だけを参照できる。
  - 参照されていないトップレベルの `const` も評価する。
- 理由: どの診断が出るかが、名前が参照されているかどうかで変わらないようにする。
- 仕様: 追記（§5・§7）

### C8 edition 宣言
- 決定: `"use cdl N";` の形のままにする。文字列は厳密に一致させる（空白は 1 つ、N は 10 進の正の整数）。引用符はどちらでもよい。すべてのファイルに必須。実装が知らない edition は E1。
- 仕様: 修正（付録B の項目を閉じる）

### C9 字句の細部
- 決定:
  - テンプレート文字列のエスケープに、`` \` `` と `\$` を加える。
  - `\u{…}` に書けるのは Unicode スカラー値だけ。サロゲートは不可。
  - 数値: `0o`、先頭が 0 の 8 進表記、BigInt は使えない。有限にならないリテラル（`1e400` など）は E0。
  - 単独の CR、U+2028、U+2029、BOM は E0。
  - span は元のソースのバイトオフセット。CRLF の正規化が影響するのは、テンプレート文字列の値だけ。
  - 文字列の長さの上限は、UTF-8 のバイト数で数える。
- 仕様: 修正（§3 のエスケープ一覧、§7 の文字列長）

### C10 構文の入れ子の深さの上限
- 決定: `Limits` に「構文の入れ子の深さ」（既定 128）を加える。oxc に渡す前に、自前の字句器で次のものの深さを数え、上限を超えたら E1 にする。
  - 括弧
  - JSX
  - 前置演算子の連なり
  - 三項演算子
- 理由: 深い入れ子でスタックがあふれると abort になり、「パニックしない」という保証が崩れる。
- 仕様: 追記（§7 のリソース上限の表）

### C11 パーサの回復
- 決定: プロトタイプでは、構文の誤りからの回復は oxc に任せる。1 回の実行で複数の誤りを報告することは、名前解決以降の段階で保証する。構文の回復テストは、自前パーサに替えるときに足す。
- 仕様: なし（§10 の保証はプロトタイプでは部分的になる、とここに記録する）

### C12 自前の字句検査
- 決定: `cdl-syntax` に小さな自前の字句器を置く。担当は E0 の検査、セミコロン必須の検査、入れ子の深さの検査（C10）。構文木は oxc で作り、CDL AST に変換する。
- 仕様: なし

## D. 評価・値・決定性

### D1 数値の文字列化
- 決定: テンプレート文字列の補間では、JS の Number→String の規則を自前で実装する。整数には `.0` を付けず、1e21 以上は指数表記にする。Rust の `Display` は使わない。
- 仕様: 追記（§5 のテンプレート文字列）

### D2 -0
- 決定: 算術の結果が -0 になったら、+0 に正規化する。
- 仕様: 追記（§7 の決定性）

### D3 `%`
- 決定: JS と同じく、結果の符号は被除数の符号に合わせる。除数が 0 なら E5。
- 仕様: 追記（§5）

### D4 リソースの数え方
- 決定:
  - ステップ: 式のノードを 1 つ評価するごとに 1。文（`return`・`if`・`switch`）を 1 つ実行するごとに 1。組み込みメソッドが処理する要素 1 つにつき 1。`concat` やスプレッドがコピーする要素 1 つにつき 1。（改訂: 文の分を足し、実装に合わせた）
  - 呼び出しの深さ: ユーザーの関数、コンポーネント、コールバックの呼び出しを数える。
  - 値木のノード数: 要素・配列・オブジェクト・葉をすべて数える。
  - 上限ごとに別の E5 コードを割り当てる。
- 仕様: 追記（§7）

### D5 段階の打ち切りと診断の順序
- 決定: 次の段階に進むかどうかは、全モジュールをまとめたプログラム全体で判断する。同じ段階の中では処理を続け、誤りを複数報告する。warning では止めない。診断は (ファイル ID, 開始, 終了, コード) の順に安定ソートする。
- 仕様: 追記（§7・§10）

### D6 値木の span
- 決定: 組み込み要素のノードには、2 つの位置を持たせる。
  - その要素を生成した JSX の位置
  - 展開の途中で通ったコンポーネント呼び出しの位置の列
- 仕様: 追記（§6）

### D7 値木の JSON
- 決定:
  - 要素: `{"element": "Name", "props": {…}, "children": […]}`
  - 単位つきの値: `{"length": 16}`、`{"duration": 120}`、`{"color": [r, g, b, a]}`
  - number・string・boolean は JSON のそのままの値。
  - 配列の中の `undefined`: `{"undefined": true}`
  - conformance の値木の比較では span を比べない。診断の比較では span を比べる。
- 仕様: 追記（§12 の適合テストスイート）

## E. スキーマ・ホスト・ポリシー・モジュール

### E1 スキーマの定義元
- 決定: スキーマは Rust 側のビルダー API でだけ登録する。CDL の中の `declare` は認めない。§6 の `declare function` は、CDL から見た型を説明するための表記として扱う。
- 仕様: 修正（§6 に注記し、付録B の項目を閉じる）

### E2 一意な子とルート
- 決定: 子が一意であることはビルダーで宣言し、評価後の値木で検査する（E4）。ルート要素の種類は、型検査の段階で静的に検査する（E4）。
- 理由: `map` が生成する子は、静的には数えられない。
- 仕様: 追記（§6）

### E3 prelude
- 決定: import しなくても使える名前は次のとおり。どれもシャドーイングできない（C6）。
  - 関数: `px`、`ms`、`sec`、`color`
  - 型: `Length`、`Duration`、`Color`、`Element`、`Array`、`Record`
- 仕様: 追記（§4）

### C10 改訂 入れ子の深さに演算子の連鎖を含める

- 仕様: 修正（§7 の表の「構文の入れ子の深さ」の説明）

## 追加の決定（意味解析）

### S1 スプレッドとキーの重なりは後勝ち
- 決定: オブジェクトリテラルと JSX の属性で、スプレッドと他のキー（スプレッドを含む）が重なったら、あとに書いたものが勝つ（TypeScript と同じ）。明示のキーどうしの重複は E3。B7 に合わせ、スプレッドの中で値が `undefined` のフィールドは、前の値を上書きしない（型の上では、省略可能なフィールドのスプレッドは前の型とのユニオンになる）。
- 理由: 既定値の一部だけを変える書き方ができる。
- 仕様: 追記（§5 のスプレッド）

### S2 条件と論理演算子は boolean だけ
- 決定: `if` と `?:` の条件（違えば E3001）、`&&`・`||`・`!` のオペランド（違えば E3006）は `boolean`（とそのリテラル型）に限る。真とみなせる値による判定はしない。
- 理由: SPEC §2「暗黙変換は存在しない」。
- 仕様: 追記（§5 の式）
- 改訂（2026-11-12）: `&&` の右辺は boolean に限らない（左辺だけ boolean）。R2 を参照。`||` と `!` は従来どおり。

### S4 式の型を合わせるときは、広いほうをとる
- 決定: `?:` の両枝・`??` の両辺・配列リテラルの要素・推論する戻り値の型は、片方がもう片方に代入できるなら広いほうの型にし、そうでなければユニオンにする（そのユニオンが B2 で許されない形なら E3001）。文脈型のもとで検査したオブジェクトリテラルの型は、文脈型そのものにする。
- 理由: B2 はオブジェクト型どうしのユニオンを許さないので、`binds[0] ?? fallback` のような書き方が通らなくなる。
- 仕様: 追記（§4）

### S3 一意な子の検査は、静的にわかる範囲を意味解析でも行う
- 決定: 子の型が 1 つの組み込みコンポーネントに定まる直接の子（JSX で書いた要素と、戻り値型が `Element<X>` のユーザーコンポーネント）は、意味解析の段階で重複を E4006 にする。`map` などが作る子は、評価後に検査する（DECISIONS E2）。
- 理由: 評価の前に見つけられる誤りは、評価の前に報告する。
- 仕様: なし

## 追加の決定（評価）

### D8 評価の誤りの位置
- 決定: 0 除算・有限でない数・整数ミリ秒にならない Duration・`color()` の書式の誤りは、その演算か呼び出しの式の位置で報告する。リソース上限の超過（E5002–E5006）は、上限を超えたときに評価していたトップレベルの宣言の位置で報告する。`const` なら名前、`export default` なら式、フックの呼び出しなら `policy` の名前。
- 理由: 上限を超えるノードは、ステップの数え方の細部で変わる。宣言の単位なら、実装に依存せず同じ位置になる。
- 仕様: 追記（§7）

### D9 評価の誤りは最初の 1 つで打ち切る
- 決定: 評価の誤り（E5xxx）が起きたら、その場で評価を打ち切り、その誤りだけを返す。
- 理由: SPEC §7「評価はその場で打ち切られ」。残りを評価しても、誤った値に依存する宣言は評価できない。
- 仕様: なし

### D10 評価器の内部エラー
- 決定: 型検査を通った式が評価で型の誤りになったら、E5000（内部エラー。実装の不具合）として返し、パニックしない。proptest（P3）で、E5000 が起きないことを確かめる。
- 仕様: なし

- 仕様: なし

## 追加の決定（点検で見つかった記録漏れ）

### C15 文字列の外の `\` は E0007
- 決定: 文字列・テンプレート・コメント・JSX の属性文字列の外にある `\`（識別子の中のエスケープ `\u0061` を含む）は、使えない文字（E0007）にする。
- 理由: 識別子にエスケープを書く方法は仕様にない。oxc は受け付けるので、自前の字句検査で弾く。
- 仕様: なし（§3 の識別子の規則のとおり）

### C16 字句の誤りがあれば、構文解析はしない
- 決定: 自前の字句検査（E0xxx・E1008）で誤りが 1 つでもあれば、oxc での構文解析を行わず、字句の誤りだけを返す。
- 理由: oxc は最初の構文エラーで止まり、回復しない。字句の誤りを oxc の構文エラー（E1001）と重ねて報告しないため。
- 仕様: なし（プロトタイプの段階の扱い。DECISIONS C11）

### C17 関数呼び出しの引数のスプレッドは書けない
- 決定: `f(...xs)` は E1005。配列・オブジェクト・JSX の属性のスプレッドは書ける。
- 理由: 関数は引数の数と型が決まっているので、配列を展開して渡す意味がない。
- 仕様: 追記（§5 の書けない構文の一覧）

### B18 配列メソッドの型の細則
- 決定: `map` の結果の要素型は、コールバックの戻り値の型を広げたもの（`xs.map((x) => "a")` は `string[]`）。`reduce` の累積値の型は、初期値の型を広げたもの（`reduce(…, 0)` は `number`）で、コールバックはその型の値を返す。`filter` の結果は、元の配列の要素型の配列（タプルは配列になる）。
- 理由: B15 はシグネチャだけで、結果の型を決めていなかった。リテラル型のまま残すと、ほかの値と合わせられない。
- 仕様: 追記（§5 の配列の操作）

### S5 ルートの指定がなくても、ルートは 1 つの要素
- 決定: スキーマにルート要素の指定がないときも、`export default` の値は 1 つの組み込みコンポーネントの要素でなければならない（E4001）。フラグメントや配列はルートにできない。
- 理由: 要素ツリーのルートは要素である（SPEC 第 6 章）。評価器はそれを前提にしている（P3 が内部エラー E5000 として見つけた）。
- 仕様: なし

### H3 `cdl check` も評価まで行う
- 決定: `cdl check`（`Engine::check`）は構文解析・意味解析に加えて評価まで行い、評価の誤り（E5xxx・評価後の E4006）も報告する。値木を出さないことだけが `cdl eval` と違う。
- 理由: 上限の超過や 0 除算も、設定の誤りとして事前に知りたい。評価は純粋で副作用がないので、検査のために評価してよい。
- 仕様: なし

### D11 値木の深さの上限（E5011）と、構文の入れ子の既定値 64
- 決定: `Limits` に `max_value_depth`（既定 64）を加える。超えたら E5011。要素・配列・オブジェクトを 1 段と数え、葉は数えない（`<Root />` は 1、`[[1]]` は 2）。
- 決定: 構文の入れ子の既定値（C10）を 128 から 64 に下げる。数え方は変えない。
- 決定: 値の深さは、配列・オブジェクト・断片・`map` の結果・要素を作った時点で検査する。ホストが `call_hook` に渡す引数も、型を調べる前に検査する。検査は明示のスタックで行い、超えた時点で打ち切る。
- 理由: `const` を連ねると、構文の入れ子の上限を抜けて、いくらでも深い値を作れる。値の `Drop`・`conforms` などの再帰があふれると abort になる。
- 既知の限界: 検査は、新しく作る値の部分木を毎回たどる。大きな値を何度も包む入力では、ステップ上限に数えない作業が増える（上限は 1 MiB のソースで抑えられる）。
- 仕様: 追記（§7 の表の行と、深さの数え方の説明）

## プロトタイプの対象外

### X1 ホストが公開する定数は、プロトタイプでは実装しない
- 決定: SPEC §9 と DECISIONS E4 にある「ホストが登録した読み取り専用の定数」（`import { monitors } from "host:contrast"` のような値）は、プロトタイプでは実装しない。スキーマのビルダーに定数を登録する口はなく、`host:` から import できるのは型と組み込みコンポーネントだけ。
- 理由: 仕様の主張（決定性・停止性・型安全）の検証に要らない。値の型をスキーマで宣言し、評価の前に値を渡す口を `Engine` に足す必要があり、公開 API が広がる。
- 仕様: なし（仕様は変えない。本実装で入れる）

### X2 edition の範囲を問い合わせる API は、プロトタイプでは実装しない
- 決定: SPEC §13 の「ホストは、対応する edition の範囲を実装側に問い合わせる」API は、プロトタイプでは実装しない。対応する edition は 1 だけで、それ以外は構文解析で E1004 になる。
- 理由: edition が 1 つしかないので、問い合わせても答えは固定。
- 仕様: なし（仕様は変えない。edition 2 を入れるときに足す）

### C18 JSX の属性文字列では文字参照を使えない
- 決定: JSX の属性文字列（`name="…"`）に文字参照（`&amp;` など）は書けない。`&` を書いたら E0008。`&` を含む文字列は `name={"a & b"}` と書く。
- 理由: React は文字参照を解釈するが、oxc は解釈しない。HTML の文字参照の表は大きく、実装ごとに食い違いやすい。拒んでおけば、あとで解釈すると決めても、既存のファイルの意味は変わらない。
- 仕様: 修正（§3 の「文字参照の扱いは未決」を、この決定に置き換える）

## 追加の決定（最終精査 AUDIT.md への対処）

### C19 前置キーワード `keyof` `readonly` `unique` `infer` `asserts` も入れ子の連鎖に数える
- 決定: 構文の入れ子の前走査（C10）の連鎖に、これらの型の前置キーワードを加える。
- 理由: oxc が再帰で読むため、数えないと 1 MiB 以下の入力でスタックが溢れて abort する（AUDIT P1）。
- 仕様: なし（SPEC §7 の「前置演算子」の範囲内）

### D12 型の大きさの上限（E3013）
- 決定: 型別名・`interface`・`const` の型は、深さ 128・ノード数 4,096 を超えたら E3013（`Ty::Error` にして続行）。別名の参照の連鎖も深さ 128 まで。値は固定で、`Limits` に出さない（型検査のクレートは `Limits` を持たない）。
- 理由: 型は所有する木として展開されるので、`type T{i} = { a: T{i-1}; b: T{i-1} }` で指数的に大きくなり、長い別名の連鎖は再帰でスタックを溢れさせる（AUDIT P2）。値木の深さの既定 64 より大きくして、E5011 の境界（D11）を変えない。
- 仕様: 追記（§7 の表）

### D13 値木の深さの検査にステップを使う
- 決定: 値を作るときの深さの検査（D11）は、たどった値 1 つにつき 1 ステップを使う。使い切ったら E5002。ホストがフックに渡す引数の検査は、予算がないので数えない。
- 理由: 共有された値（`Arc`）を木として何度もたどるため、`[a, a]` の倍々や、大きな配列を何度も包む入力で、ステップに数えられない指数・2 乗の作業になった（AUDIT P4）。D11 の「既知の限界」の見積もり（ソースサイズで抑えられる）は誤りだった。
- 仕様: 追記（§7 のステップの数え方）

### D14 文字列を作るときのステップと、テンプレートの途中の検査
- 決定: 文字列の値を作るたびに、長さ ÷ 256（切り捨て）のステップを使う。テンプレートは、パーツを足すたびに長さの上限（E5004）を検査する。
- 理由: 上限は 1 値あたりなので、異なる 32〜64 KiB の文字列を 6 万個作る約 1.5 KB の入力が 2 GiB 以上を確保できた。テンプレートは完成してから検査していたので、`${s}` を数万回書くと上限を超えて確保した（AUDIT P5）。短い文字列（256 バイト未満）は追加のステップを使わない。
- 仕様: 追記（§7 のステップの数え方）

### D15 評価の再帰の深さの上限（E5012）
- 決定: `Limits` に `max_eval_depth`（既定 128）を加える。式（`expr`）と要素（`element`）の入れ子を、関数の呼び出しをまたいで数え、超えたら E5012。位置は D8 のとおり宣言の位置。フックは呼び出しごとに 0 から数える。
- 理由: 呼び出しの深さ（64）と構文の入れ子（64）は別々に効くので、再帰の深さは両者の積になり、20 KB の入力で評価器がスタックを使い切って abort した（AUDIT P3）。既定値は、debug ビルドの 2 MiB のスレッド（`cargo test`）でも収まる大きさにした（暫定）。
- 仕様: 追記（§7 の表）

### D16 読み込むファイル数の上限（E5013）と、E4008 のメッセージ
- 決定: ホストの `Limits` に `max_modules`（既定 256。エントリを含む）を加える。上限を超えて新しいファイルを開こうとした import の位置で E5013 を返し、そのファイルは開かない。
- 決定: E4008 のメッセージには、値そのものを入れず、値の種類だけを入れる。
- 理由: 上限は 1 ファイルあたりのソースサイズだけで、リゾルバがファイルを返し続ける限り総量が無制限だった。値の `Debug` 出力は、大きな値で巨大になる（AUDIT P6・P7）。
- 仕様: 追記（§7 の表）

## 追加の決定（React 式の宣言的 UI。2026-11-12）

React の宣言的 UI に近づけるため、これまで禁止していた 3 点（テキスト子・`c && <A />`・`key`）を許可に変え、引数の分割代入を足した。仕様変更で、A1・A2・C4・S2 の決定を置き換える（各項目には改訂の注記を足した）。変えないもの（入れない）: Hooks・状態・イベントハンドラ・`ref`・Context・子としての関数（render props）。

### R1 テキスト子を許可する
- 変更前: `<Label>text</Label>` は E1009。文字列は `{"text"}` と書く（A1）。ただし `{"text"}` も、string を子に置けるコンポーネントがなく、実際には書けなかった。
- 変更後: 子に string を受け付けると宣言したコンポーネントにだけ、テキスト子と `{"text"}` を置ける。
  - 宣言: ホストの Rust API の `ComponentDef::text_children()`。ユーザー定義のコンポーネントは、`children` の型が `string[]` のとき（**U2 で改訂**: `(Element<A> | string)[]` で、要素とテキストの混在も書ける）。
  - 受け付けない位置のテキストは E3014（新設）。SPEC 第 10 章の E3/E4 の境界（ホストの組み込みへの検査は E4）の例外として、これも E3 にする（依頼が「型の診断（E3xxx）」と指定。子に置ける型かどうかの検査として扱う）。number など、string でも要素でもない子は従来どおり E4005（ホスト）・E3001（ユーザー）。
  - 評価結果の子ノードは、要素またはテキスト（string）。`cdl-eval` の `Element.children` は `Vec<ChildNode>`（`Element(Arc<Element>)` / `Text(Arc<str>)`）。
  - （**U5 で改訂**: 空白の規則は JSX の標準に合わせた。以下の「違い」の説明は、改訂前のもの。）空白の規則: 各行の前後の空白（空白・タブ・CR）を除く → 空行を捨てる → 残りを 1 つの空白でつなぐ → 何も残らなければ子にしない。依頼の文は「JSX の標準の空白規則」とあるが、その説明（各行の前後を除く・空白だけのテキストは捨てる）は、標準の規則（Babel / TypeScript。1 行のテキストの前後の空白は残り、同じ行の `<A/> <B/>` のあいだの空白も残る）と違うので、説明のほうを採った。違い: `<Label> hi </Label>` は `"hi"`（標準では `" hi "`）。要素・`{…}` をはさむと別のテキストになる（つなげない。標準と同じ）。`{"text"}` の string は加工しない。空文字列 `{""}` も、そのままテキストの子になる。
  - 文字参照（`&amp;` など）は対応しない。テキストの `&` は E1012（新設。属性文字列の E0008 に対応する、構文の帯の診断）。
  - E1009 は欠番にする（コードは表に残し、出さない）。診断コードの意味は変えない原則に従い、新しいコードを振った。
  - 字句検査: JSX の子の中の記号は構文ネスト深さの連鎖として数える（`<T extends U>(…)` のようにコードが JSX に見える場合の備え）。文章が上限（64）に当たらないよう、`,` と `;` では連鎖を数え直す。限界: `,`・`;` のない 64 個以上の記号が 1 つの要素のテキストに続くと E1008（`.` `!` など）。
  - `Node`（`cdl-host`）: `children()` は要素の子だけ（テキストを含まない）、新設の `child_nodes()` が要素とテキストの両方。参照ホストに、テキストを受け付ける `Label` を足した（`conformance/HOST.md`）。
- 理由: React 式に近づけるため。

### R2 条件描画 `c && <A />` を許可する
- 変更前: `&&` は両辺とも boolean だけ。`c && <A />` は E3006（A2・S2）。
- 変更後: `&&` の左辺は boolean だけ（number / string / undefined を含む型は E3006。メッセージは左辺だけを指す）。右辺は何でもよく、式の型は `false | B`（B が boolean なら `boolean`）。左辺が `false` なら右辺は評価しない。`||` と `!` は従来どおり。
  - `false` と `undefined` の子は、どの子の位置（直接の子・配列・フラグメントの中・ユーザー定義のコンポーネントに渡す子）にも置け、評価結果から取り除かれる。`true` と `boolean` は置けない（E4005）。
  - 型の規則: `false | B`（B は 1 つの型）を、B2 のユニオンの範囲に加えた。`Ty::union` の正規化（`false | boolean` は `boolean`）はそのまま。配列リテラルの要素などで型を広げる（B3・B4）とき、`false | B` の `false` は `boolean` に広げない（広げると `boolean | Element<A>` になり、子に置けなくなる）。
  - B は要素に限らない（`c && 5` は `false | number`）。使い道がないが、右辺の型を制限する理由もないので制限しなかった。
- 理由: React 式に近づけるため。

### R3 `key` を許可する
- 変更前: `key` 属性は E1007。要素の同一性は位置だけ（C4）。
- 変更後: `key="…"` / `key={…}`（string か number。違えば E3001。number は JS と同じ規則で文字列にする）。
  - `key` は props ではない。コンポーネントは `props.key` を読めず、props の型に `key` を書くと E3002。評価結果のノードに `key` として残る（`Element.key: Option<String>`。値木の JSON では、ついているときだけ `"key"`）。
  - 重複: 同じ親の子（フラグメント・配列の展開後）で重複したら E4011（新設。評価後に検査し、位置は 2 つ目の要素）。`"1"` と `1` は同じ key。key のない子は何個あってもよい。評価の誤りは最初の 1 つで止まる（D9）。
  - ユーザー定義のコンポーネントに付けた key は、展開後のルート要素のノードの key になる。付けなければ key なし（コンポーネントの中のルート要素の key は引き継がない。React でも、親の子の列で効く key は呼び出し側の要素のものであるため。入れ子の `Outer` → `Inner` でも、呼び出し側の key が外側から順に上書きする）。
  - 同一性は、key → ホストが宣言した識別 prop（`Keybind` の `keys` など）→ 親・位置の順（ホストの差分の規則）。識別 prop は通常の props として残る。識別 prop を宣言する専用の API は足さない（仕様にない機能を足さない）。
  - `cdl-host`: `Node::key()` を足した（`Element.key` も公開）。
- 理由: React 式に近づけるため。

### R4 引数の分割代入（1 階層・既定値つき）を許可する
- 変更前: 引数の分割代入は E1005（C1）。既定引数も E1005。
- 変更後: 関数・コンポーネントの引数に、1 階層のオブジェクトパターン `{ a, b = 既定値 }: P` を書ける。型注釈は必須（E3007。コールバック引数でも文脈から推論しない）。別名・入れ子・rest・計算キーは E1005。`const` への分割代入は従来どおり E1005（`destructuring`）。残余引数 `...xs` も従来どおり（`rest-param`）。
  - 既定値は `P` の省略可能（`?`）な prop にだけ付けられる（違えば E3015、新設）。値の型は prop の型（E3001）。付けた名前の型は、本体の中では undefined が除かれる。
  - 既定値の式は純粋で、prop の値が undefined のときだけ、呼び出しごとに評価され、ステップを消費する（JS と同じく、与えられた値があれば評価しない）。
  - 既定値の式は、同じ関数の引数が見えない場所で解決・型付け・評価する（`{ a, b = a }` は E2002）。アロー関数では、閉じ込めた外側の値は見える。引数どうしの参照を許さないのは、評価順の規則を足さずに済ませるため。
  - 型に `P` が Record・ユニオンなどオブジェクト型でないとき、分割代入は E3001。`P` にない名前は E3002。関数型（`(x: {a: number}) => …`）の引数には書けない。
  - AST: `Param.name` を `Param.pattern`（`Ident` / `Object`）に変えた（`cdl-syntax` は内部クレートなので互換性の約束はない）。
- 理由: React 式に近づけるため（`function Bind({ keys, action }: Props)` の書き方）。

## 破壊的アップデート（洗練。2026-11-12）

互換性は考えない（仕様は 0.x）。各項目に、変更前・変更後・理由・Contrast への影響を書く。

### U1 ルートをホストの環境の関数にできる（UI = f(env)）
- 変更前: `export default` は要素だけ。`Program::root()` / `document()` は `Node` / `&Element`。
- 変更後: `export default` は、要素（静的な形）か、引数 1 つの関数（`export default function App({ output }: Env): Element<Contrast> { … }`・名前のない関数・アロー関数）。
  - `export default function` は、パーサがアロー関数の式（`ExprKind::Arrow`、本体はブロック）に変換する。名前は束縛しない。
  - 引数は 1 つ（名前または 1 階層のオブジェクトパターン）。型注釈は必須で、`Env` と完全に一致（違えば E4012）。戻り値の型注釈も必須で、ホストが指定したルート要素（違えば E4001、なければ E3007）。
  - `Env` はホストが `SchemaBuilder::env(module, ty)` で宣言する（オブジェクト型で、関数型を含まない）。CDL からは `import type { Env } from "host:…"`。宣言していないホストでの関数の形は E4013（新設）。
  - `Program::render(&Value) -> Result<Arc<Element>, Diagnostic>` を足した。呼び出しごとに独立したステップ予算。1 つの `Program` を何度でも・複数スレッドから render できる（`Send + Sync`）。同じ Env からは同じ木。`Env` の値が型に合わなければ E4014（新設。位置はルートの式）。静的な形では Env を無視する。
  - 読み込み時（`load` / `check`）は、型検査とトップレベルの `const` の評価までを行い、関数の形のルートの本体は評価しない。評価の誤りは render のときに出る。
  - `Program::root()` / `document()` は `Option`（関数の形では `None`）。`Evaluated.document` も `Option`。`Program::is_function_root()` を足した。
  - CLI: `cdl eval --env <file.json>`（関数の形のルートに渡す Env）。参照ホストに Env（`output`）を足した。
- 理由: React の UI = f(props) に近づけ、出力（モニタ）ごとの設定をホストの値から宣言できるようにする。
- Contrast への影響: `program.root()` が `Option<Node>` になった。静的な設定だけを使うなら `program.render(&Value::Undefined)?` で木を得る。Env を使う場合は、スキーマで `.env(…)` を宣言し、出力が変わるたびに `render` する。

### U2 子と props の型付け: `Element<A> | string` とスロット
- 変更前: ユニオンは B2 の範囲（リテラルどうし・`T | undefined`・`Element<A | B>`・`false | B`）だけで、`Element<A> | string` は書けず、ユーザー定義のコンポーネントの子は要素だけかテキストだけ。スロットの型違いは、ホストなら E4004、ユーザー定義なら E3001。
- 変更後:
  - `Element<A> | string`（`"lit" | Element<A>`、`Element<A | B> | string` も）を、型注釈・式の型として使える。`(Element<A> | string)[]` が、要素とテキストの混在する子の型。テキストを含む子を渡す側の型は、テキストだけなら `string[]`、混在なら `(Element<…> | string)[]`（フラグメントも同じ）。`Element<A> | number` などは従来どおり E3009。
  - スロット（要素を props に渡す。`<Panel header={<Title />}>`）: 実装はすでにあった（props の型は `Element<Title>`・ユニオン・配列。値は評価結果の props に `Value::Element` として残る）。確認して、足りない部分だけを足した: 型違いの要素のスロットは E3016（新設）。依頼が E3xxx と指定したので、ホストのコンポーネントでも E4004 ではなく E3016 にする（R1 の E3014 と同じ扱い。SPEC 第 10 章に例外として明記）。要素でない値は従来の E4004 / E3001。配列リテラルの中の型違いも E3016。
  - `cdl-host`: `Node::slot(key)` / `Node::slots(key)`（D で最終形に整理する）。`false` はスロットに置けない（型が `false | Element<T>` になり、`Element<T>` に入らない）。
- 理由: 要素とテキストの混在は React の `children` の実態で、スロット（`header={<Title />}`）は React の props の要素そのもの。
- Contrast への影響: なし（追加のみ。E3014 に当たっていた混在の子が書ける）。

### U3 key は string だけ。重複は早く、すべて報告する
- 変更前（R3）: `key` は string か number（number は文字列にする）。重複は評価後に検査し、最初の 1 件で止まる。`{...{ key: "x" }}` は「props に `key` はない」と報告。
- 変更後:
  - `key` の型は string のみ。number（`number`・数値リテラル・計算結果）は E3017（新設。help に `` key={`${n}`} ``）。それ以外の型は従来どおり E3001。組み込みに number → string がないので、移行はテンプレート文字列。
  - 静的な重複: 同じ親の JSX の子（フラグメントの中を含む）の、文字列リテラルの key（`key="a"` と `key={"a"}`）どうしを、意味解析（評価の前）で、重複したものすべてについて E4011 にする（ラベルに最初の子）。ホストの組み込みコンポーネントが親のときだけ（ユーザー定義のコンポーネントの子は、それを置いた先で検査される）。動的な key（`key={k}`）は静的には比べない。
  - 評価時の重複: 評価を続けて、見つかった E4011 をすべて報告する（`evaluate` / `Program::render` は `Vec<Diagnostic>` を返す）。それ以外の評価の誤りは、従来どおり最初の 1 つで打ち切る（D9）が、そのとき見つかっていた重複も一緒に返す。位置順に並べる。
  - `{...x}` の中の `key`: 「`key` は props ではないので、`{...x}` では渡せない（`key="…"` と属性で書く）」と報告する（コードは E4003 / E3002 のまま）。
- 理由: number の key は、`1` と `"1"` の区別など、紛らわしさの元。重複は、利用者が一度に直せるよう、早く・まとめて見せる。
- Contrast への影響: `cdl_host::Program::render` と `cdl_eval::evaluate` の誤りの型が `Diagnostic` → `Vec<Diagnostic>`。`Element.key` は変わらず `Option<String>`（number を渡す書き方がなくなっただけ）。

### U4 `cdl-host` の公開 API を固める
- 変更前: `Node::name()` / `element()` / `children()` / `prop::<T>` / `optional_prop::<T>` / `expect` / `slot` / `slots`、`FromValue { const EXPECTED; fn from_value(&Value) -> Option<Self> }`（`String` / `f64` / `bool` / `Px` / `Millis` / `Rgba` のみ）。ノードの型付きの読み出し（`FromNode`）、子の型での収集、一意子の取得はなかった。
- 変更後（署名は README / HANDOFF の「安定させる面」に一覧）:
  - `Node`: `name()` → `component()`、`element()` を廃止して `props()` / `span()` / `expanded_from()` / `key()` を足した。`optional_prop` を廃止し、`prop::<T>` が、ない prop を `undefined` として読む（省略できる prop は `prop::<Option<T>>`）。`children_named(&str)`・`children_of::<T: FromNode>()`・`unique_child::<T>()`（2 つ以上あれば E4008）・`required_child::<T>()`・`read::<T>()`（コンポーネント名を確かめて読む）。`expect` は `expect_component` に改名（静的検査の `expect(` と紛らわしいため）・`slot_as::<T>()` を足した。`children()`（要素だけ）と `child_nodes()`（`Child::{Element, Text}`）は U2 までと同じ。
  - `FromValue`: `EXPECTED` 定数をやめて `fn expected() -> String`（`Vec<T>` / `Option<T>` の型名を作るため）。`Option<T>`（`undefined` なら `None`）と `Vec<T>`（`T[]`。1 要素でも読めなければ全体が読めない）を標準で実装した。
  - `FromNode`（新設）: `const COMPONENT` と `from_node(Node) -> Result<Self, Diagnostic>`。失敗は、そのノードの位置つきの診断（E4008。`Node::error`）。
  - derive マクロは作らない（proc-macro の依存を足さない）。手書きの実装例は `examples/contrast.rs`（`Appearance` ほか。`Config` が子を型で集める）。
  - `ChildNode::{Element, Text}`（評価結果の子。`Element.children`）と `Child::{Element(Node), Text(&str)}`（`Node` から読む形）の 2 つを残す。前者は所有する値、後者は借用して読む形で、責務が違う。
  - `examples/` と `conformance/HOST.md` の参照ホストを新 API に合わせた（Env・Group を足した）。
- 理由: ホスト（Contrast）が設定を Rust の型に読み出す定型を、位置つきの診断で安全に書けるようにし、公開する面を最終形に近づける。
- Contrast への影響: `Node::name()` → `component()`、`Node::element()` の削除（`props()` / `span()` / `child_nodes()` を使う）、`optional_prop::<T>("k")` → `prop::<Option<T>>("k")`、`FromValue::EXPECTED` → `expected()`（自前の `FromValue` 実装があれば書き直す）。

### U5 テキスト子の空白規則を JSX の標準に合わせる
- 変更前（R1）: 各行の前後の空白を（最初の行の先頭・最後の行の末尾も含めて）除く。`<Label> hi </Label>` は `"hi"`。
- 変更後: JSX の標準（Babel / TypeScript）と同じ。行に分け、各行の前後の空白を除く（最初の行の先頭と最後の行の末尾の空白は残す）、空行を捨て、残りを 1 つの空白でつなぐ。単一行のテキストの前後の空白は残る（`<Label> hi </Label>` は `" hi "`、`<Label>  x  \n  y  </Label>` は `"  x y  "`）。タブは変換しない（TypeScript と同じ）。
  - 標準との差（1 点）: **空白だけのテキストは、常に捨てる**。標準では、同じ行の `<A/> <B/>` の間の空白（改行を含まない空白）は `" "` のテキスト子として残る。それを残すと、テキストを受け付けない要素（`Contrast` など）の子の間の空白が、E3014 という謎の型エラーになるため。
  - `{1}` のような number の子は、従来どおり置けない（E4005）。`{""}` の空文字列の子は、従来どおり残す（変更しない）。
- 理由: 標準に合わせて、React / TSX に慣れた人の期待どおりにする。差は、利用者に謎の型エラーを見せないための 1 点だけ。
- Contrast への影響: テキスト子の前後の空白が残る場合がある（`<Label> hi </Label>`）。ホストが表示用に trim するか、CDL 側で空白を書かない。


### L1 ホストがリテラル型（列挙）を宣言できる
- 変更前: `cdl-host` が `Literal` を公開しておらず、ホストは `Ty::Literal` を作れなかった。列挙（`"alt" | "super"`）を `string` にして、自前の変換で検査するしかなかった。
- 変更後: `cdl-host` が `Literal` を再公開する（`pub use … {Field, Literal, Ty}`）。ホストは `Ty::union(vec![Ty::Literal(Literal::String("alt".into())), …])` で、props・`Env`・フックの型にリテラルのユニオンを使える。補助関数（`Ty::string_union` など）は足さない。範囲の宣言や、ユニオンの順序・比較は足さない（ユニオンは順序のない集合）。
- 動作: 範囲外の値は、props なら E4004（メッセージに型のユニオンが出る）、`Env` なら E4014。`string` 型の値はリテラルのユニオンに入らない。
- 理由: Contrast が 5 つの prop を `string` + 自前検査で回避していて、`Env` の型（列挙）も書けないため。追加だけで、既存の `.cdl` と API を壊さない。
- Contrast への影響: 列挙の prop を `Literal` のユニオンに置き換えられる。置き換えると、その検査の診断が Contrast 独自のコードから CDL の E4004 に変わる。
